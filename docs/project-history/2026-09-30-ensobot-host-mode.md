# EnsoBot 群聊主持人模式、工作可见与前端自动化测试

日期：2026-09-30。基线：EnsoBot 分支 `61aefe08`。状态：本地验证通过，未提交、未推送、未发布。

后续：上述“通过”限于当时列出的定向场景。[2026-10-04 原始设计真机验收](2026-10-04-ensobot-design-acceptance.md)
发现流式工作摘要缺失、工具结果不可查看，以及直接 @ 的活轮重启后缺少中断说明；整体设计目标尚未全部验收通过。

## 用户反馈

1. 要能看见 bot 的工作（像 Multica 那样），不能是黑箱。
2. 群聊应像 Grok 那样讨论，而不是必须一个个 @。
3. 群里哪怕 @ 了一个人也没有回复。
4. 需要一套模拟人类操作的前端自动化测试，每次更新不用真人从头点一遍。

讨论方式由用户选定：**主持人模式**（协调者拆解派发，成员互相 @，主持人汇总；接力上限默认 12 次）。

## “@ 了也没回复”的根因（开发版真实数据复现）

被 @ 的成员其实跑完了一轮，只是回复没进群：

- 人发的群消息按 `bot` 车道投递，前面垫着“这是另一个 bot 转来的话，不是用户本人”，模型据此拒绝行动；
- 只送了“@名字”这一句，前一条真正描述需求的人话没带上，模型不知道要做什么；
- 宿主只把 `ensobot_say` 气泡当回复，模型直接写的最终文字被丢掉——群里、私聊、留言板都一样。

## 这次的改动

- 宿主（`src/main/services/ensobotHost.ts`，规则纯函数在 `src/shared/ensobot/discussion.ts`）：
  人话走人的车道；没点名交给主持人；送给成员的是原话加群上下文；一轮最后的文字就是回复；
  bot 在群里 @ 别人会叫醒对方并按讨论链计次；主持人分派的成员都回报后，主持人收到汇总提醒；
  失败或无回复在群里留系统说明。详细契约见 `docs/engineering-reference/main/services.md`。
- 工作可见：快照新增 `activity`（排队/思考/输入/调用工具/重试及当前轮步骤），回复带 `work`。
- 建群可选主持人（缺省协调者）：IPC、preload、pair 协议与 `pairPolicy` 同步收窄 `hostId`。
  `@名字 (职位)` 这类名字可以用括号前的短名点到。
- 界面：群头像条（状态点、主持人皇冠）、标题下的实时状态、消息里的 @ 高亮、可折叠“工作记录”、
  正在工作成员的实时进度行（审批/提问就地显示在他的进度下面）、系统说明行、侧栏状态点与“团队动态”、
  成员页的实时状态。
- 前端自动化测试：`pnpm test:e2e:ensobot`（`e2e/ensobot/`），用法见 `docs/engineering-reference/testing.md`。
  连接方式的坑见 `big-question/electron-e2e-pinned-workbench-hang.md`。

第一轮没做、已在下文“第二轮优化”补上：建群后改主持人、消息 Markdown 渲染、讨论链持久化、
接力上限设置。

## 验证

- 单测：`ensobotHost.test.ts` 新增 10 个场景（人话身份与群上下文、最终文字回复、私聊去重与旧消息、
  失败说明、主持人默认与指定、分派—回报—汇总、成员失败回报、接力上限、活动投影与工作记录）；
  另有 `discussion` / `activity` / `rooms` / `ensobotView` / `pairPolicy` 用例。相关集合 172 个用例通过。
- 前端自动化测试 4/4 通过（约 80–100 秒）：私聊回复与进度收起、建群选主持人→不点名→主持人 @ 成员→
  成员调用 `ls` 并在工作记录里可见→主持人汇总（界面顺序与 `log.jsonl` 一致）、审批就地出现并点“允许”
  继续、重启后群/主持人/记录仍在。
- 两厂商真机（隔离 userData，用完删除）：主持人 inyx `claude-fable-5-1`（Anthropic 协议），成员 inyx
  `gpt-6-astra`（OpenAI Responses）。两人私聊都直接回复；群里不点名的问题由主持人给出初算并
  `@北北` 核对，成员回 `@阿宁 核对无误……15 小时`，主持人随后给出结论，共一次汇总、无重复。
- 全量：`pnpm typecheck` 通过；Windows 全量 Vitest 30 个文件 / 82 个用例失败，逐个对照上一轮基线
  （`temp/ensobot-main-merge-tests.log`），新增出现的文件在单独重跑时全部通过（负载下的超时），
  其余均为既有 Windows 失败（CRLF、符号链接 EPERM、路径形态等）；`biome check .` 389 个既有格式错误
  （基线 390），本次改动的文件检查干净。全量门禁仍不能算通过。

## 第二轮优化

- **群设置**：群头部新增“群设置”，可改主持人和接力上限（1–50，留空用默认 12）。宿主 `updateRoom`
  （校验在 `planRoomUpdate`），IPC `ensobot:room-update`、preload、pair `ensobot-room-update` 与
  `pairPolicy` 同步收窄；`productCapabilityCoverage` 登记为非 agent 能力。
- **Markdown**：bot 回复与留言板上 bot 的留言复用工作台的 Markdown 组件（粗体、列表、表格、代码），
  用一个 remark 插件在文本节点里保留 `@名字` 高亮；人发的消息仍按原文显示。侧栏预览去掉 Markdown 记号。
- **讨论链落盘**：`chains.json` 让重启后接力次数延续。重启时正在做的那一支如实在群里标为中断，
  不自动重做、不再让主持人等；还在排队的接力保留。
- **排队消息续送**：`resume()` 在宿主建好（worker 已在）或 worker 起来时，把从未送进会话的排队消息
  接着送；为此 `agentHost` 新增 `onAgentWorkerSpawn` 订阅。以前重启后排队消息要等用户再给那位成员
  发消息才会送出。成员已删除则丢掉。
- **接力没送到**：bot 之间的接力送不出去（离线、模型不可用）时群里说明，并按失败回报主持人。
- **细节**：就地审批不再重复“名字 · 需要审批”标题；“换掉原来的目标”改为“替换对方正在做的事”，
  只在对方正忙时出现（空闲时这句话本来就会开新一轮），并附说明。

验证：

- 单测：宿主新增 5 个场景（换主持人、按群上限、重启后续送且计数不清零、重启时中断如实说明且不重放、
  已删成员的排队消息丢弃），外加 `rooms` / `discussion` / `ensobotView` / `pairPolicy` /
  `agentHost.lifecycle` / `ensobotRuntime` 用例；相关集合 214 个用例通过，`pnpm typecheck` 通过。
- 前端自动化测试 5/5（约 20 秒）：新增“群设置”场景（真实下拉选主持人、填上限、保存后界面与
  `groups.json` 一致），群聊场景断言汇总里的粗体渲染成 `<strong>` 且界面和侧栏都不出现 `**`，
  审批场景断言就地审批无重复标题、顶部不重复、对方空闲后“替换”开关消失，重启场景确认新主持人仍在。
- 两厂商真机（隔离 userData，用完删除）：这次把主持人换成 inyx `gpt-6-astra`（OpenAI Responses），
  成员为 inyx `claude-fable-5-1`（Anthropic）。新主持人收到没点名的问题后 `@阿宁` 核对，成员回表格并
  `@北北`，主持人给出带表格的结论；界面渲染出 2 个表格，@ 在 Markdown 里仍高亮。
- 全量：Windows 全量 Vitest 26 个文件 / 79 个用例失败，与基线（`temp/ensobot-main-merge-tests.log`）
  逐条对照完全相同、没有新增；`biome check .` 仍是 389 个既有格式错误，本次改动的文件检查干净。
  全量门禁仍不能算通过。
